# Release Notes: v1.0.0
**Sprint 1.0 - Group Aggregate (Core Domain)**

## 1. Objetivo
Se implementó el Aggregate Root `Group`, representando la unidad pedagógica fundamental de la plataforma dentro de `Organization Context`, aplicando la política **Zero Legacy**.

## 2. Decisiones de Negocio
- **Aislamiento Multi-Tenant:** `TenantId`, `InstitutionId` y `CenterId` son obligatorios e inmutables.
- **Child excluido del Aggregate:** Un `Child` será un Aggregate Root independiente. `Group` gestiona cupos a nivel numérico (`occupancy` vs `maxSeats`), pero no guarda arreglos ni asociaciones directas con los registros complejos de los niños, para evitar bloqueos transaccionales (contention) y preservar los límites lógicos de DDD.
- **Inmutabilidad Defensiva:** Se aplicaron copias profundas de objetos `Date` y se validó estrictamente el uso del método `getTime()` en `check-architecture.cjs`.

## 3. Comportamiento (Behaviors)
El Aggregate Root `Group` expone constructores y métodos privados delegando la mutabilidad estrictamente a transacciones ricas semánticamente:
- `create`: Instancia un grupo y genera el evento de creación.
- `rename`: Cambia el nombre respetando invariantes de unicidad.
- `changeCapacity`: Actualiza los cupos máximos, comprobando siempre que `newMaxSeats >= occupancy`.
- `updateOccupancy`: Modifica la cantidad de alumnos inscritos lógicamente.
- `suspend`, `reactivate`, `archive`: Gestiona el ciclo de vida, generando eventos homónimos.
- `closeAcademicCycle`, `startNewAcademicCycle`: Permite la rotación generacional del grupo vaciando temporalmente el cupo ocupado.

## 4. Invariantes
- La capacidad de `maxSeats` nunca puede ser negativa.
- La `occupancy` nunca puede exceder los `maxSeats`.
- Se restringen operaciones en grupos clausurados o archivados (`CLOSED` o `ARCHIVED`).
- Transiciones inválidas retornan una abstracción `Result.fail` con tipado estricto `InvalidGroupOperationError` sin afectar el estado interno ni generar eventos fantasma.
